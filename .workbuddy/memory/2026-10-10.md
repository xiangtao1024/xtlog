## stateFile 记录逻辑答疑（xtlog-client）

用户追问 stateFile 的记录逻辑。要点（实现均在 `client/src/source.rs`）：

- 结构：`HashMap<路径字符串, 字节偏移>`，一行 JSON。key 是 config 里**原样**写的路径
  （`./app.log` 就记 `./app.log`），改写法会让旧偏移失配 → 重新按 from_start 规则定位。
- 只有 `file` 采集器写它；`cmd` 无「读到哪」的概念。
- 推进条件：poll 读到**换行边界**才推进（半行留 raw 缓冲，避免切断多字节字符）；
  单次最多读 1MB（`MAX_READ_PER_POLL`），大历史文件分多轮追上。
- 落盘：值变化才 dirty → 后台线程每 3s flush + Ctrl+C/SIGTERM 前 flush + main 结束 flush；
  先写 `.state.tmp` 再 rename，防被杀时写坏。
- 恢复：有记录从记录字节继续；无记录时 `from_start=false` → 取当前文件大小（末尾，只推新增），
  `true` → 从 0 补历史。文件大小 < 已记偏移（轮转/截断）→ 归零重读。
- **风险点**：offset 在「读出来」时推进，不等「送达服务端」。推送失败/队列满丢弃/退出没推完的日志
  不会重读（真丢）；反过来偏移没写盘（kill -9）→ 重启会重读几秒 → 重复几条。

## 轮转场景验证（同轮）

实测 rename 轮转（logrotate 式：旧文件改名 + 新建空同名文件）下 stateFile 行为：
- 轮转前 `{"info.log":158}`；rename 后新建空 info.log 并写入 47 字节 → 变为 `{"info.log":47}`，
  **归零重读新文件，不读旧内容、不重复**。代码 `size < offset → offset=0` 分支正确覆盖。
- 局限：被改名走的归档文件（date.log）**不在配置 paths 里，客户端不会采**，那段日志客户端侧漏采。
  已知的真实限制：动态日期归档名无法预列，客户端只跟踪固定路径。改进方向：加 inode(dev+ino)
  变化检测，比单纯 size<offset 更稳（防同一 inode truncate 后部分重写致前段漏读）。待用户决定是否要。

## 客户端 UTF-8 截断 panic 修复（同轮）
用户线上 Linux 跑客户端闪退：`thread panicked at src/parse.rs:216 ... end byte index 200 is not a char boundary; it is inside '企' (bytes 199..202)`。
根因：`truncate(s,max)` 用 `s[..max]` 按**字节**切，max 落多字节字符（中文/emoji）中间 → Rust 直接 abort。
`first_n(s,n)`（sender.rs:219）同样的隐患。`net.rs` 的 `text[i+4..]`（HTTP 体起点，ASCII 分隔符后，是字符边界）与
`parse.rs` 的 `line[..sp]`/`text[..nl]`（find 返回 ASCII 分隔符位置，天然边界）、`strip_cr`（`\r` 单字节结尾）均安全，未改。
`source.rs` 两处是对 `&[u8]` 切片，无字符边界检查，安全。
改动：
1. `client/src/parse.rs::truncate` 与 `client/src/sender.rs::first_n`：切片前 `while end>0 && !s.is_char_boundary(end) { end-=1 }` 退到最近字符边界。
2. `.gitignore` 增加 `xtlog-client.state` / `*.state`（相对 stateFile 运行时落在 cwd，避免污染仓库）。
验证：造 210 字节纯「企」token（首 token 横跨 200 字节）复现原崩溃；修后跑 6s 无 panic/Aborted，正常解析推送。
`cargo build --release --offline` 通过；重建 `dist/xtlog-client-0.1.0-windows-x64.zip`（341KB）。
**交付注意**：用户线上是 Linux 二进制（root@ecm...），需在其机器 `cargo build --release`（或 `./build.sh`）重编；
Windows dist zip 仅作 Windows 目标用。清理了测试产生的游离 `xtlog-client.state`/`client.out`。

## 前端日志控制台浏览器卡死/闪退修复（同轮）
用户反馈：实时日志一直看、全部日志不停往上刷都会把浏览器干卡然后标签页闪退。
根因三处（web/src）：
1. `LogConsole.vue` all 模式 `loadOlder` 是 `older.concat(rows.value)` 只增不减、无上限 → 向上不停刷把 DOM 撑到几万节点 → OOM 闪退。
2. `LogView.vue` SSE `onmessage` 每来一条就 `liveConsoleRef.push()`/`allConsoleRef.push()`/`rows.unshift()` 各一次 → 高频率下每秒几十次整列表重渲染风暴，CPU 拖死。
3. `.l-msg` 无高度限制 → 单条几千行堆栈撑成几千米高 DOM 块，布局拖爆。
改动：
- `LogConsole.vue` 新增 `ALL_CAP=2000`；`loadOlder` 超出则 `slice(0,ALL_CAP)` 丢最旧，tip 提示「已达渲染上限，更早请用时间范围筛选」；新增 `pushMany(list)` 批量追加+封顶+滚动一次；`.l-msg` 加 `max-height:360px;overflow:auto;overscroll-behavior:contain`（内容完整保留、内部滚动）。
- `LogView.vue` SSE 改为缓冲 `pending` + 每 200ms `flush()` 成批 `pushMany` 到两个控制台与表格；`pending>5000` 丢最旧防积压；`visibilitychange` 隐藏时暂停 flush，显示时恢复；`onBeforeUnmount` 清理监听与定时器。
验证：`npm run build` 通过；`mvn -s _mvn-settings.xml -DskipTests clean package` BUILD SUCCESS；
jar 内 static/LogView-*.js 含 `渲染上限`+`pushMany` 标记确认打包成功。
刷新部署包：`sh scripts/build-dist.sh` 生成 stage+tar.gz，重打成 `dist/xtlog-server-0.0.1.zip`（13.97MB，10 entries，jar 已更新）。
交付：用户部署 `target/xtlog-server.jar` 或 dist zip；浏览器需 Ctrl+F5 强刷。客户端无需重编（此次未改 Rust）。

## 日志解析支持多格式时间戳（nginx/syslog/ISO8601）（同轮）
用户反馈：采集器/推送器疑似只认 Spring Boot 日志，切到 nginx 日志就不行了；要求「适用于所有日志」。
核实：采集通吃任意文本文件，但结构化解析（多行切分/时间戳/级别）原本只认 Java 格式 yyyy-MM-dd HH:mm:ss[.SSS]。
nginx error(2026/10/10 09:15:32 [error])、nginx access([10/Oct/2026:09:15:32 +0000]) 时间戳识别不到 -> isNewEntry 返回 false -> 整份被当续行合并成一条巨型记录、时间回退接收时刻（用户说的「不行」）。
改动（服务端 LogTextIngestor.java 与推送端 client/src/parse.rs 保持同步）：
- 新增多格式时间戳识别：Java/ISO8601±tz、nginx error(yyyy/MM/dd)、nginx access([dd/Mon/yyyy:HH:mm:ss 允许行内)、syslog(Mon DD HH:mm:ss 年份取当前年)。
- isNewEntry/parseLogTime/tsEnd/guessLogger/guessThread 全部改用 has_timestamp/各 tryXxx；nginx access 时间戳不在行首允许行内匹配，其余要求行首（避免正文日期误判新条目）。
- 移除 Java 端无用 padMillis。
验证：Java 独立 harness(TsCheck) 跑 8 类样本（nginx error/warn 级别与时间正确、nginx access/syslog/ISO8601 时间正确）；合并统计 nginx error 3行->3条、Java含堆栈->仍2条(无回归)。Rust cargo test --offline 6 用例全过。
构建：mvn -s _mvn-settings.xml -DskipTests clean package BUILD SUCCESS(jar 含 TS_NGINX_ACC)；cargo build --release --offline 通过。刷新 dist/xtlog-client-0.1.0-windows-x64.zip(345KB) 与 dist/xtlog-server-0.0.1.zip(14MB)。文档：client/README.md 与 README.md 加「不挑日志格式/支持格式」说明。
