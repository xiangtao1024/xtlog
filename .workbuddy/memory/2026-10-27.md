# 2026-10-27 工作日志

## 1. 竞品分析(咨询)

对 xtlog-server 做了竞品对比分析,关键结论:
- **真实生态位**:"能在 512M 内存 VPS 上 5 分钟搭起的统一日志台",不是 ELK 的功能子集
- **真实对手**:Seq / Papertrail / Better Stack / 「tail -f + 多 SSH 窗口」自建方案,不是 ELK/Loki
- **真正护城河**:5 分钟单机起一套、不挑日志格式、CMD 采集器(journalctl/docker logs 直喂)、来源 IP 一等公民、xtlog-client(Rust)
- **真实短板**:告警未做(路线图 P1 未交付)、无集群、HTTPS 未内置、社区薄
- **建议**:把告警提到 P0、明确不做集群但加冷备、HTTPS 内置、放大 CMD 采集独特卖点、对标叙事换为 Seq/Papertrail

## 2. 告警模块(v0.0.2,端到端落地)

按"补齐告警 = 从玩具变工具"的建议,本轮完成了完整告警链路。

### 后端
- `DataSourceConfig.ensureAlertTables()` 新增两张表:
  - `xt_alert_rule`(规则:id/name/app_id/rule_type/rule_expr/window_sec/threshold/silence_sec/channels(JSON)/enabled/remark)
  - `xt_alert_event`(事件:id/rule_id/rule_name/app_id/app_name/level/summary/sample_message/hit_count/status/first_time/last_time/ack_time/ack_user),带 `idx_alert_event_status`、`idx_alert_event_rule` 索引
  - 字段定义走 `colDef(holder, name, sqliteType, flag)` 方言适配,MySQL/PG 升级时自动转 BIGSERIAL/LONGTEXT
- `AlertController`(`/api/alert/rules` + `/api/alert/events`):
  - 规则 CRUD、启停 toggle、`/test` 复用 `AlertEngine.evaluate` 给「写规则前先验证命中数」用
  - 事件列表(分页+status/ruleId 过滤)、`/ack` 认领、`/resolve` 标记恢复
  - SQLite 单写者撞锁统一走 `DbBusyRetry.retry(..., 8, 200L)`
- `AlertEngine`(`@XtScheduled(fixedRate=30000)`):
  - 每 30 秒扫一次启用的规则,在评估窗口内对月表做 UNION ALL 聚合
  - 4 种规则类型:
    - LEVEL → `level IN (...)` 多级逗号分隔
    - KEYWORD → `message LIKE '%kw%'`
    - REGEX → 拉候选行(最多 1000 条)Java 侧 `Pattern` 过滤(为兼容各库正则函数差异)
    - RATE → 同 LEVEL,靠短窗口+高阈值表达速率
  - 触发流程:命中数 ≥ threshold → 查最近 status=1 事件 → 静默窗口内合并(累加 hit_count)/过期则关闭旧事件+创建新事件 → 调 Webhook
  - 自动恢复:`checkRecovery()` 对所有 status=1 事件用其规则重新评估,命中数 < threshold/2 → status=2;规则被删的事件直接恢复
  - Webhook:`CompletableFuture.runAsync` 异步调用,HttpURLConnection 5s 超时,失败只记日志;payload 手写 JSON 转义,含 event_id/rule_name/hit_count/sample_message 等字段
  - **评估逻辑抽成 `public static MatchResult evaluate(...)`,Controller 的 testRule 直接复用,保证「测试」与「实际触发」条件一致**
- 编译踩坑:
  - xtboot 的 `@RequestBody` 不支持 `required` 属性(不像 Spring),ack 接口原写 `@RequestBody(required = false) Dict body` 编译失败 → 改成强制 body + 内部 `body == null` 兜底
  - `DbBusyRetry.retry` 抛 checked Exception;在 AlertEngine 私有方法里直接裸调用导致编译失败 → 加 `tryRetry(desc, action)` helper 包裹吃掉异常(告警旁路不能反噬主流程)
