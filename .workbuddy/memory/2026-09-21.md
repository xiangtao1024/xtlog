## xtlog-server 项目规划

产出完整规划方案：`E:\workspace\xt\doubao\demo01\docs\xtlog-server-规划方案.md`

项目定位：轻量统一日志服务（ELK/Graylog 的单机替代品），覆盖多来源日志收集、统一管理、Web 查看分析。

### 用户已确认的四项关键决策
1. **xtboot 源码可控** —— 自研 Java 框架，可边做业务边给框架补能力（路由/IoC/JDBC/数据源热装配/方言/SSE-WS/定时任务等，已列 12 项能力清单）
2. **存储**：SQLite 默认 + MySQL/PG 可选，按月分片 + 方言抽象；检索用 FTS5/FULLTEXT 并支持降级到 LIKE
3. **查看体验**：WebSocket 实时跟随 tail -f + 历史游标分页回溯
4. **首版范围**：一次性做全（含告警规则、统计大盘）

### 核心技术约定
- 写入全异步：有界队列 → BatchWriter 单一写者批量 JDBC；洪峰采样丢弃但 ERROR 永不丢
- 日志主表按月分片 `xt_log_entry_YYYYMM`，查询用游标（ts_id）而非 offset
- SQLite 必开 WAL + busy_timeout；保留策略默认 7 天
- 前端 Vue3 + Element Plus，产物打进后端 resources/static 出单 jar
- 默认端口 9009，数据目录 ./data
- 里程碑 M0-M9，建议先打通 M0-M2 最小闭环（框架能力 → Setup 向导 → curl 打日志 → 页面看到）

## JDK 8 决策 + xtboot 改造清单 + 原型（本轮产出）

### 决策
**用户拍板：统一 JDK 8。** xtboot 维持 target 1.8，xtlog 业务模块跟随。规划文档 8.5 节已标注。

### 产出文件
- `docs\xtboot-改造清单.md` —— 逐文件读源码（EmbeddedHttpServer / DispatcherHandler / JsonUtils / DbClient / CorsFilter）后整理的清单
- `prototype\index.html` —— 10 页 Element Plus 风格原型（向导/登录/大盘/应用列表/日志Console/采集源/接入指南/告警规则/告警事件/系统设置）

### 读源码挖到的关键事实（重要，别再重复分析）
- **DbClient 没有 batchInsert**：全类搜不到 addBatch/executeBatch，只有单条 insert(Object) / insert(String,Dict)。日志场景必须补（P0-1）
- **getConnection() 无池化**：dataSource 为 null 时每次 DriverManager 新建物理连接；PooledConnection 存在但不自动装配（P0-2）
- **EmbeddedHttpServer 固定线程池** `max(4, CPU*2)`，com.sun.net.httpserver 是每请求一线程模型 → SSE 长连接会占满线程让服务假死（P0-4，最容易被忽略）
- **DispatcherHandler 已支持 HttpExchange 参数直注入**（第 290 行）→ SSE 可兜底绕过框架，但干净做法是加 SseEmitter 返回值识别（P0-3）
- **writeResponse 无条件 outputStream.close()** → 不支持流式，需改造
- **CorsFilter 已有**（filter 包，支持 preflight/credentials/exposedHeaders）→ 别重复造
- **静态资源只注册 /static 前缀**，其他全走 dispatcher 404 → Vue Router history 模式刷新必 404，需 SPA fallback（P0-5）
- **JsonUtils 反射无缓存**（每次 getDeclaredFields + setAccessible）→ 高频序列化需补元数据缓存
- **JsonUtils 不支持 Date/LocalDateTime**，会静默返回全 null 不报错 → 实体统一用 Long 时间戳
- 方言缺 MySQLDialect / PostgreSqlDialect（有 LimitOffsetDialect 兜底）

### 下一步建议（已向用户提出）
先做两项 30 分钟技术验证：① SSE 在 EmbeddedHttpServer 上能否跑通（唯一技术不确定性，阻塞 M6）；② batchInsert + SQLite 写入吞吐压测（目标 >1 万条/秒）。
