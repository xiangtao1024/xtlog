## 09:32 Linux systemd 服务文件（用户要求）

- 新增 **`deploy/service/xtlog.service`**，包内路径 `service/xtlog.service`；README 加了 systemd 部署章节。

- 关键点：`Environment="JAVA_HOME=/usr/local/jdk-17"`（用户只改这一行）、`ExecStart=${JAVA_HOME}/bin/java ...`、
  classpath 顺序 `config:jar:drivers/*`（config 在前才会覆盖 jar 内置配置）、
  `ExecStop=/bin/kill -TERM $MAINPID` + `SuccessExitStatus=143` + `Restart=on-failure` + `TimeoutStopSec=20`。
- **坑 1**：systemd 展开 `${VAR}` 后**不会按空格拆词** → 不能写 `Environment="JAVA_OPTS=-Xms256m -Xmx1g"` 再 `${JAVA_OPTS}` 引用，
  否则整串变成一个参数，JVM 报 `Unrecognized option`。内存参数直接写进 ExecStart，已在文件注释里写清原因。
- **坑 2**：`.service` 文件必须 **LF**（已确认 0 个 CR），CRLF 会让 JAVA_HOME 值带上 `\r` 导致启动失败。

## 新增 CMD 命令采集器（journalctl 等非文件源接入）

需求：`systemctl/journalctl` 类日志既不是文件也不是 HTTP，用户要求「配置时直接填采集命令」。

实现：
1. **库表迁移**：`app` 表加 `cmd` 列（`DataSourceConfig.addColumnIfMissing`：SQLite PRAGMA 探列 + ALTER；
   非 SQLite 回退裸 ALTER 忽略重复列错）。
2. **抽取 LogTextIngestor**（@Component）：FileCollector 的多行合并/时间戳解析/级别与 logger 推断整体搬入，
   FileCollector 只留字节偏移/编码/目录扫描，委托 ingestor。新方法 `pushLine(app,line)`（流式续行缓冲）+
   `flush(app)`（进程退出/停止时刷尾）+ 256KB 强制切段兜底（防无时间戳纯流把内存撑爆）。
3. **CommandCollector**（@XtScheduled 5s reconcile）：CMD 应用 spawn `/bin/sh -c`（Win 用 `cmd /c`，
   支持管道重定向），stderr 合并进 stdout；退出后 3s 退避重启；应用删除/改命令时停旧启新。
4. **前端 AppView**：来源类型加 CMD 单选 + 命令 textarea；列表来源 chip 蓝色 CMD。

**关键坑——进程树查杀 race**：Windows `destroyForcibly()` 只杀顶层 cmd.exe，`cmd /c python …` 的孙进程
变孤儿继续写日志（实测删除应用后日志从 line 37 涨到 80）。`taskkill /T` 本身有效，但必须
**`tk.waitFor()` 等 taskkill 枚举完进程树再 destroy 主进程**——先 destroy 会让子进程被过继、/T 找不到树。
用 `_KillProbe.java` 单独验证：waitFor 版本子进程全部终止。Linux 同理 `pkill -P` 先于 destroy（PPID 未变时才找得到）。
pid 用反射读 `Process#pid()`（Java 9+），JDK8 拿不到退化为只杀主进程。

**环境坑（本轮）**：PowerShell 工具被沙箱废掉（exit 1 且文件写不出），npm/mvn/taskkill 全走 Bash；
Git-Bash 里 `taskkill` 别名是坏的，必须用 `/c/Windows/System32/taskkill.exe //PID x //F`（参数用 //）；
`wmic.exe` 在沙箱黑名单。

验证：流式 python 脚本每秒一行 → 创建 CMD 应用 9s 内出日志（级别/时间戳解析正确）→ 删除应用 →
python 进程消失（tasklist 0 个）。截图 `docs/screenshots/42-cmd-collector.png`。
产物重新出包：`dist/xtlog-server-0.0.1.zip` 13.43MB（含 README 5.1 节 CMD 说明）。

用户反馈：FILE/CMD 采集打的本机 IP 是 `172.27.0.1`，不是真实 IP。

**根因**：旧 `HostAddresses` 是「取第一个非回环、已启用网卡的 IPv4」。
机器上 WSL2/Hyper-V 虚拟交换机（`vEthernet (WSL)` → 172.27.0.1）、Docker 网桥（docker0 → 172.17.0.1）
在枚举顺序里常排在真实网卡前面，于是被误选。

**重写 `HostAddresses`** 为「打分优选」：
1. **手动指定最优先**：`-Dxtlog.host.ip=` 或环境变量 `XTLOG_HOST_IP`（多网卡/容器兜底）。
2. 网段打分：`192.168.*` +100 > `10.*` +90 > `172.16~31.*` +50（Docker/WSL 段压低）> 其他 +40；
   `169.254.*`、`127.*` 直接丢弃。
3. 网卡打分：有 MAC +20；名称命中 docker/veth/wsl/vethernet/virtual/vmware/tap/tun/vpn/tailscale 等关键字 −60；
   `isVirtual()` −40；`isPointToPoint()` −30。
4. 出网路由探测：UDP `connect` 到 223.5.5.5:80（只查路由表、不发包）拿到源 IP，命中则 +50。
5. 多候选时启动打印 `[xtlog] host ip: x (nif), candidates [...]` 便于核对；日志用 ASCII
   （Windows 控制台默认 GBK，中文会乱码，与 CommandCollector 现有 ASCII 风格一致）。

**坑**：`NetworkInterface.isPointToPoint()` 抛受检 `SocketException`，必须 try-catch（`isVirtual()` 不抛）。

本机实测：`localIp()=192.168.31.49 (wlan2) score=110`，VirtualBox 虚拟网卡 `192.168.56.1 (eth4)` 掉到 score=0。

## 16:45 新增 xtlog-client（客户端采集推送器，Rust 子项目）

需求：日志不在 xtlog 所在机器时，用一个二进制 `./xtlog-client --config=config.json` 采集本机
文件/命令并推给服务端。配置项：`server` + `collectors` 数组（每项 = 一个应用：token、appId、
type=file/cmd、paths 或 command）。

**技术选型**：用户选了 Rust（本机有 cargo 1.89）。
- **坑1**：`cargo build` 卡死 → 用 `--offline` 或放在 Windows 路径下（Git-Bash 的 `/tmp` 路径会挂）。
  实测 `cargo build --release` 24s 正常。
- **坑2**：Windows 上**无法交叉编译 Linux**。`-C link-self-contained=+linker` 与
  `-C linker-flavor=gnu-lld` 都是 unstable（需 nightly），且本机无 gcc/mingw；WSL 被沙箱黑名单拦截。
  → 交付「源码 + build.sh」，Linux 二进制需在 Linux 上 `cargo build --release` 产出。

**实现**（`client/`，依赖仅 serde/serde_json/chrono/encoding_rs/ctrlc）：
- `config.rs` 配置解析+校验；`parse.rs` 行解析（**对齐服务端 LogTextIngestor**：行首时间戳、
  级别词表、logger 推断、256KB 强制 flush），额外解析线程名（HTTP 上报可带 thread 字段）；
- `source.rs` 文件 tail（按字节切分避免多字节字符被截断、轮转检测=文件变小、GBK/UTF8、
  偏移持久化 stateFile）+ 命令采集（stderr 合并、退出 3s 重启、按 pid 杀进程树）；
- `sender.rs` 按采集器攒批 + 定时 flush + 退避重试 + queueMax 丢弃；
- `net.rs` 纯标准库 HTTP POST（**只支持 http://**，https 明确报错）；
- `host.rs` 用 UDP connect 探测「去往服务端」的出口 IP（不发数据包），回环/链路本地会被过滤后
  退到公网 DNS —— 天然避开 WSL/Docker 虚拟网卡。

**关键修正**：文件采集原实现只在「下一条日志出现」时才吐出上一条，导致**文件停写后最后一条永远
发不出去** → 改为「空闲（本轮没读到新行）即 flush 缓冲」。

**验证**（E2E，本地 18080）：file 与 cmd 两条链路都通，级别/日志时间/logger/线程/src_ip 全部正确
（src_ip=192.168.31.49），多行堆栈合并正确，stateFile 落盘正常；
Ctrl+Break 优雅退出（退出码 0，打印"累计推送 N 条"）。
注：Windows 用 `CREATE_NEW_PROCESS_GROUP` 启动的进程 **Ctrl+C 被禁用**，测试要用 CTRL_BREAK_EVENT。

**交付**：`dist/xtlog-client-0.1.0-windows-x64.zip`（338KB，含 exe + 示例配置 + README + build.sh）；
`deploy/README.md` 新增 5.2 节「远程机器的日志怎么采」。`.gitignore` 加 `client/target/`。
