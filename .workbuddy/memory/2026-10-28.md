## 修复：删除应用残留日志（BUG1）+ 应用启用/停用（BUG2）

### 现象
- 删除应用后，该应用的日志仍留在各月表里（孤儿日志）。
- 需要新增「启用/停用」开关：停用后拒收 HTTP 推送、停止 CMD/FILE 采集；启用后恢复。

### 改动文件
- `AppService.java`
  - `AppInfo.enabled` 字段默认 `true`；`loadAll()` 解析 `enabled` 列。
  - 索引重建改为「先建新 HashMap 再整体 volatile 替换引用」，避免 refresh 期间并发读者
    把存活应用误判为「已删」而丢日志（为落库判活兜底）。
- `DataSourceConfig.java`：迁移 `app.enabled` 列（INTEGER，默认启用）。
- `AppController.java`
  - `create()` 默认 `enabled=1`；`update()`/`setEnabled()` 处理 enabled 字段。
  - `delete()` 顺序修复：先 `queue.removeByApp(id)` 丢弃在途日志 → `deleteAppLogs(id)` 清库
    （含 FTS 孤儿索引项清理）→ 删 app 行 → `refresh()`。杜绝「删完库行又被落库线程写回
    复活」的竞态（之前测出会复活 6 条）。
  - 新增 `DELETE /api/apps/{id}/enable`（`setEnabled`）与私有 `deleteAppLogs`/`ftsTableExists`。
- `IngestController.java`：`!app.enabled` 时直接返回 `disabled:true, accepted:0`，日志不落库。
- `CommandCollector.java` / `FileCollector.java`：`!app.enabled` 跳过（不启动/停掉采集进程）。
- `IngestQueue.java`：新增 `removeByApp(long)`，删除前清空队列里该应用的待落库日志。
- `LogBatchWriter.java`：注入 `AppService`，落库前用 `resolveById` 判活，应用已删的日志直接丢弃
  （与 `delete()` 顺序共同关闭并发复活竞态）。
- 前端 `web/src/api/index.js`（新增 `appApi.setEnabled`）、`web/src/views/AppView.vue`
  （状态列 + 启用/停用按钮 `toggleEnabled`）。

  启用→`accepted>0`、库增加（BUG2 PASS）。

## 修复：停用按钮不生效 + 操作按钮整理

### 现象
- 点「停用」后一直提示「已启用，开始接收日志」，状态列也不切换。
- 操作列按钮太多（查看日志/开发配置/编辑/启用停用/删除），需要收敛。

### 根因
- 前端 `toggleEnabled` 用 `const target = !(row.enabled === false)` 取反，**恒为 true**：
  当前启用时 `row.enabled`(true/1/null) `=== false` 都是 false → `!false=true` → 反而去「启用」。
- 后端 `list()` 直接返回 DB 的 `enabled`（INTEGER 0/1，存量 NULL），前端 `=== false` 永远不成立，
  状态列对 `enabled=0` 也会误显「启用中」。

### 改动
- 后端 `AppController.list()`：返回前把 `enabled` 统一归一为**布尔**（`parseEnabled()` 辅助：
  NULL→true，0→false，其余→true）。与 `AppService.loadAll()` 保持一致，彻底消除 0/false 类型歧义。
- 前端 `AppView.vue`
  - 新增 `isDisabled(row)` = `row.enabled === false || row.enabled === 0`（兼容两种形态）。
  - `toggleEnabled` 改为 `const isOn = !isDisabled(row); const target = !isOn;`，逻辑正确。
  - 操作列收敛为 **3 个**：`查看日志` + `编辑`（常驻）+ `更多`(下拉：`启用/停用` / `开发配置` / `删除`)。
  - 状态列、下拉项文本均改用 `isDisabled(row)` 判断。

### 验证
- 隔离实例（18091）e2e：`list` 返回 `enabled` 已是布尔 `True/False`；
  停用→列表 `False`、推送 `disabled:true, accepted:0`；重新启用→`True`、推送 `accepted:1`。全部 PASS。
- 前端 `npm run build` + `mvn clean package`（端口恢复 18080）产物 `target/xtlog-server.jar`。
- 测试产物 `data_test/`、`_server_18091.log` 已清理；未动用户 18080 调试服务。

### 注意
- 用户本机 18080 仍是旧代码（IDE 调试进程，基于 target/classes）。**重新部署/重启新 jar** 后，
  停用按钮才生效、操作列才是新布局。存量 DB 启动自动补 `enabled` 列，旧应用默认启用。
